# 安全与合规

> 全量安全基线（已实现）。涉及认证、授权、限流、上传、隐私与 AI 生成内容的规则；开发与评审按本文执行。

## 1. 威胁模型（摘要）

| 威胁 | 场景 | 控制 |
| --- | --- | --- |
| 越权（IDOR） | 修改 URL 访问他人频道/帖子/私信 | 服务端逐资源校验；所有频道操作走 `ChannelAccessService` |
| 私密内容泄露 | 未加入用户读取私密频道 | 可见性校验（ADR-0005）；查询层强制过滤；专项测试 |
| 凭证攻击 | 撞库、暴力破解 | BCrypt(≥12)、登录限流、失败计数、密码强度校验 |
| 令牌泄露 | XSS 窃取 localStorage | access token 仅存内存；refresh token HttpOnly Cookie |
| 注入 | SQL/命令/模板注入 | 参数化查询；禁止拼接 SQL；输出转义 |
| XSS | 帖子/评论富文本 | 服务端白名单净化（Jsoup），禁止原始 HTML 直出 |
| CSRF | 携带 Cookie 的写请求 | SameSite=Lax + 关键写操作不使用 Cookie 鉴权（JWT Header） |
| 恶意上传 | 脚本/超限文件 | MIME+magic 校验、扩展名白名单、大小限制、重命名存储、禁止执行 |
| 垃圾内容 | 批量发帖/评论 | 限流、频率限制、举报与人工处置（M2） |
| AI 提示注入 | 用户诱导 AI 越权回答 | 上下文只含公开内容；系统提示约束；输出审核与免责声明 |
| 数据泄露 | 日志/导出含敏感信息 | 日志脱敏；导出权限校验；最小化采集 |

## 2. 认证与会话

- 密码：BCrypt cost 12；注册时校验 8–64 位、包含字母与数字。
- access token：JWT HS256（默认）或 RS256（后续），有效期 15 分钟；claims 含 `sub`(userId)、`iat`、`exp`、`jti`。
- refresh token：随机 256-bit，存 SHA-256 哈希；有效期 7 天；HttpOnly + Secure + SameSite=Lax；每次刷新轮换，旧令牌撤销。
- 登出：撤销 refresh token；access token 依赖短有效期。
- 令牌密钥：环境变量注入（`JWT_SECRET`），禁止入库/入仓；不同环境不同密钥。
- 游客：公开只读接口匿名可访问；写接口一律 401。

## 3. 授权

- 权限点定义见 [需求规格 §2.2](03-需求规格.md)；身份组 `permissions` JSON 存储权限点集合。
- 频道访问判定顺序：频道是否存在/未解散 → 可见性（游客/成员）→ 成员身份 → 权限点（含板块范围）→ 业务状态（禁言/封禁）。
- 所有管理操作（置顶/精华/删除/成员/身份组/邀请）必须校验权限点并写入审计日志。
- 权限矩阵必须有自动化测试（角色 × 操作 × 预期结果）。

## 4. 输入与输出

- 所有请求体使用 Jakarta Validation 校验；字符串长度、枚举、URL 格式、媒体数组上限。
- 富文本：服务端 Jsoup 白名单净化（允许的标签/属性白名单），禁止 `script`/`style`/事件属性/危险 URL 协议。
- 评论/帖子输出按上下文转义；前端渲染富文本只使用净化后的 HTML。
- 分页参数上限限制（`limit ≤ 100`）；搜索关键词长度 ≤ 100 且转义通配符。
- 排序/筛选字段白名单，禁止用户输入直接进入 SQL/ORDER BY。

## 5. 上传与媒体

- 图片：JPG/PNG/WebP/GIF，≤ 10MB；视频：MP4/WebM，≤ 200MB。
- 校验 MIME + 文件头 magic number，不信任扩展名；随机文件名存储。
- 上传目录不在 Web 根可执行范围；Nginx 以静态资源方式提供。
- 图片生成缩略图；视频 M1 不转码，限制格式与大小。
- 媒体 URL 使用不可猜测路径；删除媒体仅限本人且未被引用（M2）。

## 6. 传输与浏览器安全

- 全站 HTTPS（生产）；HSTS。
- CORS：仅允许配置的前端域名，允许凭据时禁止 `*`。
  - 精确来源走 `setAllowedOrigins`，含通配符的条目（如 `http://127.0.0.1:*`）走 `setAllowedOriginPatterns`；
    Spring 不允许把通配符放进 `allowedOrigins`。
  - **开发环境默认同时放行 `localhost` 与 `127.0.0.1`**：浏览器把它们视为不同来源，而 Vite 代理会把
    原始 `Origin` 透传给后端（Host 被改写为后端端口），只放行其中一个会让另一个地址下所有接口返回
    `403 Invalid CORS request`（前端表现为「无法连接服务器」）。
  - 生产必须用 `CORS_ALLOWED_ORIGINS` 显式列出正式域名，不要保留 `*` 通配。
- API 无状态，不使用服务端 Session；CSRF 风险由 SameSite + Header 鉴权控制。
- 安全响应头：`X-Content-Type-Options: nosniff`、`Content-Security-Policy`（前端由 Nginx 配置）、`Referrer-Policy`。

## 7. 限流与防滥用

| 接口 | 限制（初始值） |
| --- | --- |
| 登录 | 每 IP + 用户名 10 次/分钟 |
| 注册 | 每 IP 5 次/小时 |
| 发帖 | 每用户 10 次/分钟、每频道 60 次/小时 |
| 评论 | 每用户 30 次/分钟 |
| 上传 | 每用户 30 次/小时 |
| 搜索 | 每用户 60 次/分钟 |
| AI 问答 | 每用户每日配额 200 次 + 并发 1 |

- 超限返回 429 + `Retry-After`（秒），错误码 `RATE_LIMITED`。
- 实现：`com.isles.common.ratelimit`（`@RateLimit` 注解 + `RateLimitInterceptor` + 固定窗口计数）。
  - `app.rate-limit.store=memory`：进程内计数，单机默认；
  - `app.rate-limit.store=redis`：`INCR` + `EXPIRE` 共享配额，多实例部署使用；Redis 异常自动降级为内存计数并告警。
  - `app.rate-limit.trust-forwarded-for=true`：部署在 Nginx 之后时按 `X-Forwarded-For` 首个地址计数。
  - `app.rate-limit.enabled=false` 仅用于本地联调/自动化测试。

## 8. 日志与审计

- 访问日志记录 `requestId`、userId（登录时）、路由、状态、耗时；不记录密码、令牌、完整 Cookie。
- 管理日志（M2）：频道内管理操作与关键用户行为，字段含 actor、action、target、detail、ip、time。
- 日志保留策略：应用日志 30 天；审计日志 ≥ 180 天（可配置）。

## 9. 隐私与合规

- 最小化采集：手机号/邮箱在需要时再采集；当前仅用户名/昵称/头像/签名/性别/地区。
- 用户可修改资料；提供账号注销（M2）与数据导出（M3）。
- 用户协议、隐私政策上线前由负责人确认（合规文本不在本期开发范围）。
- AI 生成内容标注"由 AI 生成"，并允许用户反馈/举报。

## 10. 实现与待办

已实现：

- 权限校验统一入口 `ChannelAccessService`（可见性 → 成员 → 权限点 → 板块范围 → 禁言/封禁）。
- 登录/注册/发帖/评论/上传/搜索限流（`RateLimitInterceptor`），429 + `Retry-After`。
- 富文本服务端 Jsoup 白名单净化（`HtmlSanitizer`）；输出按上下文转义。
- 上传类型/大小校验、随机文件名、目录不在 Web 根；`/uploads/**` 只读静态服务。
- refresh token 哈希存储（SHA-256）+ 轮换；access token 仅存前端内存。
- 管理日志（`channel_audit_logs`）覆盖频道内写操作与关键管理操作。
- 举报处置（频道管理 + 平台后台）与结果通知。
- AI：上下文只取公开帖子/本频道内容；API Key AES-GCM 加密落库；生成内容带 AI 标识与免责声明。

待办：

- 安全响应头与 CSP 在 Nginx 配置（部署阶段）
- 权限矩阵自动化测试（角色 × 操作 × 预期）
- 富文本净化白名单评审
- 密钥管理与轮换流程（部署阶段）
