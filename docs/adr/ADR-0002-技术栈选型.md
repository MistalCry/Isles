# ADR-0002：技术栈选型（Spring Boot 4.1 + Vue 3）

## 状态

已采纳（Accepted）· 2026-11-14 · 决策来源：项目负责人选定方向，由技术侧完成版本与配套选型

## 背景

项目是一个长期演进的社交频道平台，首个形态为响应式 Web，后续计划部署到自有服务器并扩展桌面客户端。需要确定前后端、构建、UI 与部署技术栈，且必须与本机开发环境兼容。

约束：

- 负责人明确倾向：**Spring Boot + Vue**、**MySQL + Redis**、WebSocket 实时、Docker Compose 单机部署。
- 本机已具备：JDK 17.0.12（`JAVA_HOME`）、Maven 3.9.4、MySQL 8.0.45（服务运行中）、Node 26.7.0、pnpm 11.24.0；未安装 Docker、Redis。
- 单人 + AI 辅助开发，技术栈需要"文档与生态成熟、AI 可稳定产出代码、排障成本低"。

## 候选方案

### 方案 A：全栈 TypeScript（Next.js + NestJS）

- 优点：单语言、前后端类型共享、开发速度快。
- 缺点：与负责人偏好不符；Java 生态的长期可维护性与招聘面在此项目不占优。

### 方案 B：Spring Boot + Vue（采纳）

- 优点：
  - 与负责人技术偏好一致，社区与中文资料丰富，长期维护与招聘面好。
  - Spring 生态在安全（Spring Security）、实时（WebSocket/STOMP）、数据访问、Actuator 监控上配套完整。
  - Vue 3 + TypeScript + Element Plus 适合快速构建响应式 Web 界面。
  - 本机 JDK 17 + Maven 就绪，无需额外安装即可开发后端。
- 缺点：
  - 双语言栈，前后端类型无法自动共享（用 OpenAPI 契约缓解）。
  - Spring Boot 4 / Spring Security 7 较新，部分第三方库适配需验证。
  - 相比 Node，单机内存占用更高。

### 方案 C：.NET 10 + React

- 优点：性能强、SignalR 实时成熟、本机已安装 .NET 10。
- 缺点：与负责人偏好不符；团队（负责人）对 Java/Spring 更熟悉。

### 方案 D：Go + Vue

- 优点：部署简单、资源占用低。
- 缺点：业务开发效率低于 Spring；生态与负责人偏好不符。

## 决策

采纳**方案 B**，具体版本与配套：

| 项 | 选型 | 版本基线 |
| --- | --- | --- |
| 后端语言 | Java | 17（LTS，`JAVA_HOME` 指向 JDK 17.0.12） |
| 后端框架 | Spring Boot | 4.1.2（当前稳定版） |
| 构建 | Maven | 3.9.4（单模块） |
| 前端 | Vue 3 + TypeScript + Vite | 3.5.x / 5.x（TS）/ 8.x |
| UI | Element Plus | 2.14.x |
| 状态/路由 | Pinia / Vue Router | 3.x / 4.x |
| 认证 | Spring Security + JWT（jjwt） | Boot 管理 / 0.13.0 |
| 实时 | Spring WebSocket + STOMP | Boot 管理 |
| 数据库 | MySQL 8.0（utf8mb4） | 8.0.x |
| ORM | MyBatis-Plus | 3.5.18（`spring-boot4` starter） |
| 缓存 | Redis | 7.x（本地 Memurai 兼容） |
| 迁移 | Flyway | Boot 管理 |
| 部署 | Docker Compose + Nginx | — |

验证：`Spring Boot 4.1.2 + Java 17 + spring-boot-starter-web/websocket/data-redis/security/validation + mybatis-plus-spring-boot4-starter 3.5.18 + mysql-connector-j` 依赖组合已在本机通过 `mvn compile`。

## 后果

### 正面

- 与负责人偏好一致，降低长期维护与沟通成本。
- Spring 官方对安全、实时、监控、数据访问均提供成熟方案，符合规范中的安全与可观测性要求。
- 依赖组合已实测可构建，降低踩坑风险。

### 负面 / 成本

- 前后端双语言：通过 OpenAPI 契约 + TypeScript 类型生成（后续可选）降低不一致风险。
- Spring Boot 4 使用 Jackson 3、Spring Security 7 等较新组件，第三方库（如 MyBatis-Plus）适配需持续验证；通过集成测试与版本锁定控制风险。
- Java 17 虽为 LTS，但项目周期长，后续可按需升级到 Java 21/25（升级前需评估 Spring Boot 4 兼容性）。

### 风险与缓解

- 风险：Boot 4 新版本特性与社区资料不匹配 → 缓解：以官方文档与集成测试为准，关键配置写 ADR/架构文档。
- 风险：Vue 生态版本升级快 → 缓解：锁文件提交、月度升级窗口、CI 校验。
