# 架构决策记录（ADR）

> ADR（Architecture Decision Record）用于记录**重大技术决策**及其上下文，避免决策只存在于聊天记录或某人脑中。
> 规则：一决策一文件、编号递增不复用、已批准 ADR 不修改（只能追加补充说明或被新 ADR 替代）。

## 何时必须写 ADR

- 技术栈 / 框架 / 数据库 / 中间件选型
- 架构风格与模块边界（单体/微服务、前后端分离方式、服务间通信）
- 认证授权模型、数据一致性策略、缓存策略
- 第三方服务引入（支付、存储、推送、监控、邮件等）
- 破坏性变更、有争议的权衡、不可逆决策

**不需要**写 ADR：可逆的小实现选择、规范已覆盖的内容、纯局部重构。
