# ADR-0005：频道类型与邀请机制

## 状态

已采纳（Accepted）· 2026-11-14

## 背景

需求的频道类型需要同时满足"开放社区"与"封闭圈子"两种使用场景：

- 兴趣社区希望任何人都能发现并加入频道（公开）。
- 私密圈子希望只通过邀请进入，且可以对加入者进行审批、控制可见性。

负责人确认：**公开 + 私密邀请**两种；私密频道通过邀请链接加入，可设置是否需要审批，可设置可见性。

## 候选方案

### 方案 A：仅公开频道

- 优点：实现最简单，发现与增长最快。
- 缺点：无法满足私密圈子需求，所有内容对全站可见。

### 方案 B：公开 + 私密邀请（采纳）

- 优点：覆盖两种主流场景；邀请链接天然适合站外传播（QQ/微信/游戏群）；可见性可单独控制。
- 缺点：需要邀请链接、加入审批、可见性三套规则，数据模型与权限校验比方案 A 复杂。

### 方案 C：公开 / 需审批 / 私密邀请（三种独立类型）

- 优点：粒度最细。
- 缺点：概念重叠（"需审批"可视为私密 + 审批），增加用户理解成本与实现复杂度，首版收益低。

## 决策

采纳**方案 B**，规则如下：

### 频道类型

| 类型 | 加入方式 | 是否可被搜索/推荐 |
| --- | --- | --- |
| `PUBLIC` 公开 | 自由加入（无需审批） | 是 |
| `PRIVATE` 私密 | 仅通过邀请链接加入；链接可配置是否需要审批 | 默认否；可见性为公开可见时可被搜索到（但不能直接加入） |

### 私密频道可见性

| 可见性 | 含义 |
| --- | --- |
| `PUBLIC_VISIBLE` | 未加入用户可浏览频道页与公开帖子，但不能发帖/评论，需邀请加入 |
| `MEMBERS_ONLY` | 仅成员可浏览；非成员访问返回 404/无权限，不出现在搜索结果 |

### 邀请链接

- 由拥有 `channel.invite.create` 权限的成员创建；链接携带随机 token（不可猜测，存库哈希）。
- 可配置：是否需要审批、有效期（可空）、最大使用次数（可空）、是否启用。
- 使用链接后：
  - 无需审批 → 直接加入；
  - 需要审批 → 生成 `join_request`，管理员/频道主在成员管理或审批列表处理（M2）。
- 邀请链接可撤销；撤销后立即失效。

### 数据与权限

- `channels` 增加 `type`、`visibility` 字段。
- 新增 `channel_invites`（token 哈希、审批开关、有效期、次数、创建者）与 `join_requests`（申请人、状态、审批人）。
- 新增权限点：`channel.invite.create`、`channel.invite.approve`、`channel.visibility`。
- 公开只读接口（M1）：公开频道与 `PUBLIC_VISIBLE` 私密频道的频道页/帖子详情允许游客访问；`MEMBERS_ONLY` 频道仅成员可见。

## 后果

### 正面

- 一套模型同时覆盖开放与封闭社区，避免后期加类型时的大改。
- 邀请链接便于站外传播，符合社区增长需求。
- 可见性与加入审批分离，运营可灵活组合（如"可浏览但需审批加入"）。

### 负面 / 成本

- 权限与可见性判断点增多，必须集中到 `ChannelAccessService`，并配权限矩阵测试。
- 审批队列、邀请链接管理增加 M2 工作量。

### 风险与缓解

- 风险：可见性规则遗漏导致私密内容泄露 → 缓解：所有频道相关查询必须经过 `ChannelAccessService`；为"私密/仅成员"写专项测试。
- 风险：邀请 token 被暴力猜测 → 缓解：足够长的随机 token + 存哈希 + 限流。
- 风险：分享的邀请链接被滥用 → 缓解：有效期、最大次数、可撤销。
