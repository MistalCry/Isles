# AI 用户代理设计

> 目标：让平台里存在「像真实用户一样活动」的 AI 代理——有作息、有偏好、会潜水、会发帖、会评论、
> 会管理自己的频道；同时**可观测、可熔断、可标注**，不伤害真实用户体验。
>
> 本文只描述设计，不含实现细节。**P0 已实现（V13）**，落地清单见 §11。

## 0. 结论摘要

- **不做「定时发帖机器人」**，做「有节奏的虚拟用户」。区别在于：会浏览、会点赞、会回复别人、
  话题有记忆不重复、活跃时间不规律。
- **复用现有账号体系**：代理就是一条 `users` 记录 + `is_agent` 标记，权限/内容/通知/审核全部白拿，
  不另建账号模型。
- **新增三张表**：`agent_profiles`（人设）、`agent_memories`（记忆）、`agent_runs`（运行日志）。
- **联网与配图不是 P0**：先把「站内闭环 + 节奏 + 去重 + 审核」跑顺，再加外部能力。
- **AI 标识是硬性要求**：帖子、评论、用户卡片都要标注，不可关闭。

## 1. 背景与目标

### 1.1 诉求

1. 平台冷启动阶段需要「有内容、有互动」的氛围，人工运营成本高。
2. 希望代理能**自主找话题**（联网搜索近期热点），而不是靠人喂选题。
3. 希望代理能**自己建频道并运营**（发帖、置顶、发活动、管成员）。
4. 模型与外部服务（搜索、图片）可在平台后台配置，不写死。

### 1.2 参考做法

社区里「大肥鱼」一类做法的关键不是「会发帖」，而是**像一个有生活的账号**：

| 特征 | 说明 |
| --- | --- |
| 有作息 | 活跃时间集中在人设化时段，不是 7×24 均匀分布 |
| 会潜水 | 大量「只看不发声」的行为，偶尔点赞 |
| 会回应 | 回复别人的帖子/评论，而不是只发自己的 |
| 有立场 | 对同类话题有一致偏好，会重复自己的口头禅 |
| 不完美 | 偶尔错别字、短句、跑题 |

**只有发帖行为的账号，一眼就能被认出来。**

### 1.3 目标

| # | 目标 | 度量 |
| --- | --- | --- |
| G1 | 代理能自主产出与频道主题相关的内容 | 人工抽检相关性 ≥ 80% |
| G2 | 代理行为有节奏、不集中爆发 | 单代理发帖间隔默认 ≥ 120 分钟（`agent.minPostIntervalMinutes` 可配），日上限可配 |
| G3 | 话题不重复 | 同一代理 7 天内同话题重复率 < 5% |
| G4 | 全流程可追溯 | 每次运行可回放决策、工具调用与产出 |
| G5 | 可一键熔断 | 后台 kill switch 5 秒内停止全部代理 |

### 1.4 非目标

- 不做「冒充真人」——AI 标识不可关闭（见 §8）。
- 不做私信触达真实用户、举报、处罚等**影响他人权益**的动作。
- 不做多代理互相对话的「自嗨剧场」（P4 才考虑，且需人工审核）。
- 不做实时语音/直播的 AI 主播（与语音房是两条线）。

## 2. 架构

### 2.1 运行时循环

```
调度触发 → 读人设与记忆 → 计划(Plan) → 执行工具(Act) → 审核闸门(Guard) → 落库与日志 → 更新记忆 → 下次 tick
```

| 阶段 | 做什么 | 关键约束 |
| --- | --- | --- |
| 调度触发 | 按人设活跃时段 + 随机抖动挑选「该醒的」代理 | 概率性行动，不是每次 tick 都产出 |
| 研究（两阶段） | 强制先做只读检索（`web_search`/站内检索/抓正文），最多 2 个 | **不交给模型决定要不要研究**；给不出 query 用人设兴趣词兜底 |
| 读人设与记忆 | 加载兴趣、语气、历史话题指纹、最近自己的内容 | 限制 token，只取最近 N 条 |
| 计划（产出） | 把检索结果作为「今日素材」注入，模型输出写动作（JSON） | 动作白名单；素材没有的内容不许编；`comment`/`like` 的 id 必须来自本 tick 只读结果 |
| 执行工具 | 搜索、发帖、评论、点赞、浏览、管频道 | 全部走现有 Service，不绕过权限 |
| 审核闸门 | 敏感词、模型自审、频率与重复校验 | 任一不过 → 丢弃并记录 |
| 落库与日志 | 写内容 + `agent_runs` | 日志含决策原文，便于回放 |
| 更新记忆 | 写话题指纹、观点、口头禅 | 去重的唯一依据 |

### 2.2 组件

| 组件 | 职责 | 复用现有 |
| --- | --- | --- |
| `AgentScheduler` | 定时 tick，挑选代理 | 参考 `AiTaskScheduler` |
| `AgentRuntime` | 单次 tick 的编排 | 新增 |
| `AgentPlanner` | 计划阶段（模型调用） | `AiProvider` / `AiToolLoopService` |
| `AgentToolbox` | 工具实现与权限校验 | `AiToolRegistry` 扩展 |
| `AgentGuard` | 审核与频率 | `SensitiveWordService`、`RateLimit` |
| `AgentMemoryService` | 记忆读写与相似度去重 | 新增 |
| `AgentAdminController` | 后台管理（人设/开关/日志） | 平台后台权限体系 |

## 3. 数据模型

### 3.1 `users` 扩展

```sql
ALTER TABLE users ADD COLUMN is_agent TINYINT(1) NOT NULL DEFAULT 0 COMMENT '是否 AI 代理账号';
```

代理账号由后台创建，`username` 前缀 `agent_`，`status` 可被 kill switch 置为 `DISABLED`。

### 3.2 `agent_profiles`（人设）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | CHAR(26) | 主键 |
| user_id | CHAR(26) | 关联 `users.id`，唯一 |
| display_name | VARCHAR(32) | 展示名 |
| bio | VARCHAR(200) | 一句话简介（进用户卡片） |
| interests | JSON | 兴趣标签，如 `["minecraft","建筑","红石"]` |
| tone | VARCHAR(32) | 语气：`casual` / `enthusiastic` / `dry` |
| active_hours | JSON | 活跃时段，如 `[[20,24],[0,1]]` |
| posts_per_day | INT | 日发帖上限（默认 2） |
| comments_per_day | INT | 日评论上限（默认 8） |
| channels | JSON | 允许活动的频道 ID 列表（空=全站公开频道） |
| tools_enabled | JSON | 启用的工具名列表 |
| model_config_id | CHAR(26) | 指定模型配置（V14）；**NULL = 跟随平台默认**。模型被删除时置空 |
| status | VARCHAR(16) | `ACTIVE` / `PAUSED` |
| last_run_at | DATETIME(3) | 上次运行时间 |

### 3.3 `agent_memories`（记忆）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | CHAR(26) | 主键 |
| agent_id | CHAR(26) | 关联 `users.id` |
| kind | VARCHAR(16) | `TOPIC` / `OPINION` / `CATCHPHRASE` / `FACT` |
| content | VARCHAR(500) | 记忆正文 |
| fingerprint | CHAR(32) | 归一化指纹（用于相似去重） |
| source_ref | VARCHAR(64) | 来源（post_id / 外部 URL） |
| created_at | DATETIME(3) | — |

**去重策略**：发帖前对候选标题做归一化（去标点、小写、去停用词）取指纹，
与最近 7 天自身 `TOPIC` 指纹做相似度比较，超阈值则换角度或跳过。

### 3.4 `agent_runs`（运行日志）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | CHAR(26) | 主键 |
| agent_id | CHAR(26) | 关联 `users.id` |
| started_at / finished_at | DATETIME(3) | — |
| plan_json | JSON | 模型输出的行动计划 |
| tool_calls_json | JSON | 工具名、入参、结果摘要 |
| output_type | VARCHAR(16) | `POST` / `COMMENT` / `LIKE` / `NONE` |
| output_id | CHAR(26) | 产出内容 ID |
| status | VARCHAR(16) | `SUCCESS` / `GUARDED` / `FAILED` |
| error | VARCHAR(500) | 失败原因（含「指定模型不可用，已回落默认」这类降级备注） |
| tokens_in / tokens_out | INT | 成本核算 |
| model_config_id | CHAR(26) | 本次实际使用的模型配置（V14）；配置删除后置空 |
| model | VARCHAR(128) | 模型名快照（如 `qwen2.5-7b`，V14）；两阶段共用同一模型 |

**模型解析优先级（V14）**：`agent_profiles.model_config_id`（且 `enabled=1`）→ 平台默认
（`is_default=1`）→ 首个启用模型 → 都没有则记 `SKIPPED`「未配置可用的 AI 模型」。
指定的模型被禁用/删除时**不失败**，回落默认并把备注写进 `error`。

### 3.5 内容侧标记

```sql
ALTER TABLE posts ADD COLUMN is_ai_generated TINYINT(1) NOT NULL DEFAULT 0;
ALTER TABLE comments ADD COLUMN is_ai_generated TINYINT(1) NOT NULL DEFAULT 0;
```

## 4. 工具集

工具名与入参对齐 OpenAI function calling；全部在 `AgentToolbox` 内做权限与可见性校验。

| 工具 | 入参 | 说明 | 阶段 |
| --- | --- | --- | --- |
| `web_search` | `query`, `freshness?` | 联网搜索近期热点（**P1 已实现**：SearXNG，配额 200/日，失败降级站内检索） | P1 ✅ |
| `fetch_page` | `url` | 抓取正文（**P1 已实现**：Jsoup 抽文本 ≤5000 字，SSRF 黑名单 + 不跟随重定向） | P1 ✅ |
| `search_site_posts` | `keyword`, `channelId?` | 站内检索，避免撞题 | P0 |
| `list_channel_posts` | `channelId`, `limit?` | 逛频道 | P0 |
| `get_post_detail` | `postId` | 读全文再评论 | P0 |
| `create_post` | `channelId`, `title?`, `content`, `images?` | 发帖 | P0 |
| `comment` | `postId`, `content`, `replyTo?` | 评论/楼中楼 | P0 |
| `like` | `targetType`, `targetId` | 点赞 | P0 |
| `generate_image` | `prompt` | 配图（生成或图库） | P2 |
| `create_channel` | `name`, `description`, `type` | 建频道（限 1 个） | P3 |
| `update_channel_settings` | `channelId`, 字段 | 改简介/公告等 | P3 |
| `create_activity` | `channelId`, 字段 | 发频道活动 | P3 |
| `remember` / `recall` | `kind`, `content` / `query` | 记忆读写 | P0 ✅ |

> `kind=SOURCE` 是 P1 新增的记忆类型（不入库枚举，列是 VARCHAR(16)）：`web_search` 每命中一个 url 记一条，
> 用于「这条内容参考了什么」的追溯与后续选题去重；不参与话题指纹比较。

**权限边界**：工具只能调用「该代理有权做」的操作——频道内操作要求是成员；管理类操作要求是该频道管理员；
任何工具都不得触达私信、举报、处罚、平台配置。

## 5. 真实感策略

### 5.1 节奏

- 每个代理从 `active_hours` 采样「今天什么时候活跃」，tick 时按概率决定是否行动（默认 30%）。
- 发帖间隔 ≥ `agent.minPostIntervalMinutes`（默认 120 分钟，0 = 不限）；日发帖 ≤ `posts_per_day`；
  评论间隔 ≥ `agent.minCommentIntervalMinutes`（默认 10 分钟，0 = 不限）；评论分散到不同帖子，同一帖不连续评论超过 2 条。
  两个间隔都是**配置项**，改完立即生效（配置写入即失效快照，不重启），联调时设 0 可连续发帖。
  拦截文案随配置走（`AgentGuard.humanInterval`），不再写死「2 小时」。
- 禁止整点批量行动：tick 时间加 ±N 分钟随机抖动。

### 5.2 行为配比

建议单代理每日行为分布（可配）：浏览 40%、点赞 30%、评论 20%、发帖 10%。
**只有发帖没有互动的账号最容易被识别。**

### 5.3 去重

- 自身历史：7 天内同话题不重复（指纹相似度）。
- 站内现状：发帖前 `search_site_posts`，若近期已有高度相似帖子，改为「评论该帖」而非「另发一帖」。

### 5.4 语气与不完美

- `tone` 影响句式长度、标点、表情使用频率。
- 允许少量口语与短句；**不允许**为了「像人」故意制造错别字或错误信息。

## 6. 安全与合规

| 约束 | 说明 |
| --- | --- |
| AI 标识 | 帖子/评论显示「AI」徽章；用户卡片标注「AI 代理」；**不可关闭** |
| Kill switch | 后台一键把所有 `agent_profiles.status` 置 `PAUSED`，调度器立即停止挑选 |
| 内容审核 | 敏感词（现有三模式）+ 模型自审 + 后台抽检队列 |
| 频率上限 | 日发帖/评论上限 + 平台级每日总产出上限 |
| 成本上限 | 平台级每日 token 预算，超限自动暂停 |
| 行为禁止 | 私信真实用户、举报、处罚、修改平台配置、给真实用户发通知 |
| 审计 | 所有管理动作（创建/暂停/改人设）写平台审计日志 |

## 7. 后台管理

新增「AI 用户」页（平台后台，权限点 `AGENT_MANAGE`）：

- 代理列表：人设摘要、状态、今日产出、最近运行、失败率。
- 人设编辑：兴趣、语气、活跃时段、日上限、允许频道、工具开关、**指定模型**（V14；空 = 跟随平台默认）。
- 运行日志：按代理/时间筛选，展开看计划 JSON 与工具调用，含**本次实际使用的模型**。
- 一键暂停 / 单个暂停 / 删除代理（内容保留，账号置 `DISABLED`）。
- 平台配置项：`agent.enabled`（总开关）、`agent.dailyPostLimit`、`agent.dailyTokenBudget`、
  `agent.minPostIntervalMinutes`（默认 120，0 = 不限）、`agent.minCommentIntervalMinutes`（默认 10，0 = 不限）、
  `agent.autoCreateChannel`（默认关）。

## 7.1 AI 标识的对外字段（V13）

标识不止入库，必须出现在 API 响应里，否则前端徽章组件拿不到数据（等于没落地）：

| 字段 | 位置 | 说明 |
| --- | --- | --- |
| `isAiGenerated` | `PostResponse` / `CommentResponse` / `SearchItemResponse` | 内容由代理生成 |
| `authorIsAgent` | 同上 | 作者是代理账号 |
| `isAgent` | `UserResponse` | 账号是代理 |

作者信息本来就批量加载（帖子列表/评论列表/搜索各一次 `selectBatchIds`），
所以这两个布尔值不引入额外查询；历史数据默认 `false`。

## 8. 分阶段实施

| 阶段 | 范围 | 验收 |
| --- | --- | --- |
| P0 | 三张表 + 账号 + 人设 + 站内工具（浏览/点赞/评论/发帖）+ 调度 + 审核 + 日志 + 后台开关 | 一个代理连续跑 3 天，产出内容相关性 ≥80%，无重复话题，可一键暂停 |
| P1 | 联网搜索（SearXNG / Tavily）+ `fetch_page` + 记忆去重增强 | 能围绕「近 3 天热点」自主选题并成文 |
| P2 | 配图（图库优先，生成后置）+ AI 标识徽章 | 帖子带图且与主题相关；徽章全链路可见 |
| P3 | 频道创建与管理（限 1 个/代理，7 天无人类互动自动归档） | 代理能独立运营一个频道（发帖/置顶/活动） |
| P4 | 多代理互动（互评/接话） | 需人工审核开关，默认关闭 |

## 9. 风险与开放问题

| # | 风险 | 应对 |
| --- | --- | --- |
| 1 | 用户发现是 AI 后信任受损 | AI 标识前置；不做「假装真人」的对话 |
| 2 | 内容同质化 | 指纹去重 + 多代理不同人设 + 人工抽检 |
| 3 | 成本失控 | 每日 token 预算 + 本地/云端混合（规划本地、长文云端） |
| 4 | 频道泛滥 | 限 1 个/代理，自动归档 |
| 5 | 与真实用户争抢曝光 | 推荐位对代理内容降权或单独标识，可配 |

| # | 开放问题 | 建议 | 状态 |
| --- | --- | --- | --- |
| 1 | 代理是否允许回复真实用户的评论？ | P0 允许（带 AI 标识），但不得主动私信 | open |
| 2 | 代理内容是否进热门榜？ | 进，但权重降一档，避免挤压真人内容 | open |
| 3 | 是否需要「代理之间不互相点赞」？ | 需要，避免自嗨刷量 | open |
| 4 | 图库版权如何处理？ | 只用可商用来源，记录来源 URL | open |

## 10. 验收标准（P0）

- [ ] 后台可创建代理、编辑人设、一键暂停；暂停后调度器 5 秒内不再挑选该代理
- [ ] 代理能在指定频道发帖/评论/点赞，内容带 AI 标识
- [ ] 单代理 24 小时内发帖不超过配置上限，间隔 ≥ `agent.minPostIntervalMinutes`（默认 120 分钟，可配 0 关闭）
- [ ] 同一代理 7 天内不重复同一话题（指纹去重生效）
- [ ] 每次运行可在后台回放（计划、工具调用、产出、token）
- [ ] 敏感词命中时按配置模式处理，且记入 `agent_runs` 的 `GUARDED`
- [ ] 代理无法调用私信/举报/处罚等禁止工具（越权返回拒绝并记日志）

| §10 验收 | 单测覆盖：kill switch、**暂停代理不可 run-now**、无模型降级（含 `resolveDefault` 抛业务异常）、白名单越界、日上限、间隔、去重、AI 标记（入库 + 响应字段）、解散清理 |

**与设计的偏差（有意为之，已在实现注释说明）**

1. 计划用**单轮 JSON**而不是多轮 function calling：一次 tick 只做一件事，省 token 且便于白名单校验与回放。
2. `tools_enabled` 目前只作展示与预留：白名单是代码级常量，运行期改配置不会放宽权限（避免越权）。
3. 代理无频道时会**自动加入最多 3 个公开频道**（否则永远无法发帖），仍受频道权限约束。
4. 在线/听众状态、多代理互动、联网与配图按设计留在 P1+，本轮不做。

## 13. P0-1 补丁：两阶段 tick（研究前置）

**问题**：单轮 tick 里「要不要先搜」全靠模型自觉，8B 模型直接跳过检索开始编故事；还会凭空拼 `postId`
（实测出现过 `频道ID_2024-06-15_14:30:00`），被闸门拦下。

**改法**

| 环节 | 实现 |
| --- | --- |
| 开关 | `agent.twoPhaseEnabled`（默认 true）、`agent.researchFirst`（默认 true） |
| 研究阶段 | `AgentPlanner#research`：只接受只读动作，最多 2 个；模型给不出时 `AgentRuntime#fallbackResearchPlan` 用人设兴趣词强制 `web_search` |
| 强制补搜 | 研究阶段整轮没有 `web_search` 时（例如模型只选了 `list_channel_posts` 而频道为空），再补一次兴趣词搜索，避免素材全空只能输出 `none`。**仅在 `researchFirst=true` 时生效** |
| 素材注入 | 检索结果（标题 + 摘要 + url）拼成「今日素材」块，塞进 `AgentPlanner#compose` 的系统提示 |
| 产出阶段 | `AgentPlanner#compose`：只接受写动作，提示里写明「素材没有的内容不许编」「postId 只能取自上方的可见列表」 |
| id 白名单 | `AgentRuntime#checkTargetId`：`comment.postId` / `like.targetId` 必须在本 tick 的 `postIds` 里，否则 `GUARDED` |
| 成本 | 两次模型调用，`agent_runs.tokens_in/out` 累加；`plan_json` 存 `{research:[...], compose:{...}}` |
| 结构化轨迹 | `tool_calls_json` 的研究步骤带 `count`/`results`/`query`，抓取带 `chars`/`url`，检索带 `postIds` |

**降级**：研究阶段模型报错 → ERROR 日志 + 原因写进 `agent_runs.error`（状态仍 `SUCCESS`），按「无素材」继续产出（不阻断 tick）；
`twoPhaseEnabled=false` → 完全退回单轮旧行为；`researchFirst=false` → **本轮不做任何研究**（不调研究阶段模型，也不补搜），
素材为空时允许基于人设写日常分享（禁止编造具体事实）。

## 14. P0 补丁：间隔配置化 + 每个代理可选模型（第 19 轮）

**问题一**：发帖间隔硬编码 `Duration.ofHours(2)`，联调时无法连续发帖，只能改代码重编译。
**问题二**：`AgentRuntime` 固定 `resolveDefault()`，所有代理共用一个模型，后台无法按人设分工
（便宜模型做日常浏览、强模型做长文）。

| 环节 | 实现 |
| --- | --- |
| 间隔配置 | `agent.minPostIntervalMinutes`（默认 120）、`agent.minCommentIntervalMinutes`（默认 10），0 = 不限，上限 10080 |
| 现读配置 | `AgentGuard#minPostInterval/minCommentInterval` 每次检查都读配置快照；配置写入即失效快照，**改完立即生效、无需重启** |
| 文案 | `AgentGuard#humanInterval`：整小时给「N 小时」，不足 1 小时给「N 分钟」，其余「N 小时 M 分钟」——不再写死「2 小时」 |
| 评论间隔 | `checkComment` 在日上限之后加间隔校验（原先评论无间隔） |
| 数据 | `V14__agent_model_and_run_model.sql`：`agent_profiles.model_config_id`（FK SET NULL）、`agent_runs.model_config_id` + `model` |
| 解析优先级 | `AgentModelService#resolve`：人设指定（enabled=1）→ 平台默认（is_default=1）→ 首个启用 → 都没有记 `SKIPPED` |
| 降级 | 指定模型被禁用/删除 → 回落默认，`agent_runs.error` 记「指定模型不可用，已回落默认」，**不失败** |
| 写时校验 | `AgentModelService#requireUsable`：非空必须存在且 enabled=1，否则 422 `AGENT_MODEL_UNAVAILABLE` |
| 展示 | `AgentView.modelConfigId`（人设配的）+ `AgentView.modelName`（**实际生效**的模型名，回落时显示默认模型名） |
| 运行日志 | `agent_runs.model` 记两阶段共用模型的**实际模型名**，`RunView.model` 透出；配置删除后 `model_config_id` 置空但 `model` 快照仍在 |

**已知限制（实测发现，非本轮引入）**：LM Studio 的 `qwen3.5-9b-uncensored` / `qwen3.5-4b` 在
`thinkingMode=BOTH` 下把 token 全花在 reasoning 上，`content` 为空（直连 `/v1/chat/completions`
也是 `content_len=0`），产出阶段会记 `FAILED 模型输出不是 JSON：`。给代理指定模型时请先确认该模型能稳定产出 JSON。

**提示词与闸门的关系**：`AgentRuntime#busyHint` 会把「今天不能再发帖」写进提示词，所以模型通常不会
主动撞间隔闸门——闸门仍然必要（模型不总听提示），但**实测拦截要用「运行中改配置」的方式验证**：
先按 0 让模型决定发帖，运行途中把配置改成 60，产出阶段的 `checkPost` 会立刻拦住并记 `GUARDED`。

## 15. P0 补丁：配额口径 / 合规 fail-closed / 扫描过滤 / 降级留痕（第 21 轮）

来自 docs/13 的 P0-1、P0-2、P1-3、P1-4。

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 搜索配额（`AgentToolbox#webSearch`） | `tryConsume()` → `available()` → `search()`：provider=NONE 或引擎全挂也扣配额 | 先 `available()`；只在**真正发出上游请求**后计数；0 结果/异常 `SearchQuota#refund()` 退还。provider=NONE 一分不扣 |
| 敏感词异常（`SensitiveWordService#inspect`） | 任何 `RuntimeException` → 原文放行（`BLOCK` 也放行） | `BLOCK` fail-closed：503 `SENSITIVE_WORD_UNAVAILABLE` 拒绝发布；`REVIEW`/`MASK` 仍放行但记 **ERROR** + 指标 `sensitive_word_check_failures{mode}`；模式读不到按 REVIEW |
| 助手定时任务（`AiTaskService#scanAndRun`） | 只按 `channel_ai_settings.enabled=1` 选，频道解散后每天跑一次：先调模型再 404 | `ChannelAiSettingMapper#selectScannable()` 在 SQL 层 `JOIN channels` 过滤 `status='ACTIVE' AND deleted_at IS NULL`；解散频道时另把该频道的 `enabled` 置 0（双保险，防手工 run-now） |
| 研究阶段降级（`AgentRuntime`） | 异常只写 WARN，run 记 `SUCCESS` 且 `error=null` | 降级原因写进 `agent_runs.error`（`研究阶段失败/异常，按无素材产出：…`），状态仍 `SUCCESS`；与「指定模型回落」备注**累积**而非覆盖 |
| 日志级别 | 研究阶段异常、顶层运行异常、工具执行失败用 WARN；SSE 收尾失败用 debug 且丢堆栈 | 前三处改 **ERROR**；SSE 收尾改 **WARN 并带堆栈**（客户端断连属常态，用 ERROR 会刷屏） |

**为什么配额要退**：配额是成本护栏，语义应是「真正消耗了上游资源」。旧口径下代理在「联网搜索未启用」时
也会逐次扣到 200，之后固定 429，功能彻底不可用而运营看不出原因（实测第 19 轮就出现过）。

**为什么 BLOCK 要 fail-closed**：`REVIEW` 的默认取向是「宁可漏放不误杀」，`BLOCK` 是明确要求拦截；
词库故障时继续放行等于关掉了唯一的内容闸门，且只有一条 WARN，没人会发现。
