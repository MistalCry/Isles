## 3. 内部实现顺序（非用户分期）

1. **数据层先行**：Flyway V2（管理/私信/统计/审计）、V3（AI/平台后台）— 迁移只追加。
2. **权限与实时基础**：身份组权限点、平台管理员角色、WebSocket/STOMP 配置。
3. **管理端 API + 页面**：频道设置 → 管理中心 → 内容/成员/板块/日志/数据 → 举报。
4. **私信/好友 + 实时推送**。
5. **热门/推荐/搜索增强**。
6. **AI 问答 → 频道助手 → 平台后台 AI 配置**。
7. **部署与联调**：Docker Compose、Redis、E2E、性能与安全检查、文档收尾。

> 并行的前端与后端通过 `docs/05-API设计.md` 契约协作；路由/入口等共享文件由 Lead 统一集成，避免冲突。

## 4. 验收标准（全量）

- 所有 FR 条目（docs/03 §4）在 Web 端可操作，权限边界正确（越权返回 403/404）。
- 后端 `mvn -B test` 全绿；前端 `pnpm build` 通过；API 冒烟与关键 E2E 通过。
- 频道管理中心、私信、热门/推荐、频道问问、频道助手、平台后台可在本地跑通（LMStudio 不可用时优雅降级并有配置页）。
- Docker Compose 可在服务器/本地（具备 Docker 时）一键启动 nginx + backend + mysql + redis。
- 文档与代码一致：需求、架构、API、DB、安全、路线图、CHANGELOG 同步更新。

## 5. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 本机无 Docker/Redis | 部署与限流验证受限 | 限流先实现内存/Caffeine 适配器，Redis 适配在 Compose 中验证；Compose 文件交付并在服务器验证 |
| LMStudio 未运行/无视觉模型 | AI 功能无法真实联调 | 实现 OpenAI 兼容客户端 + 可配置 BaseURL/模型；用本地 mock OpenAI 服务做自动化测试；页面提示配置状态 |
| 全量范围大 | 一次性验收压力大 | 工作包拆分 + 共享契约；每完成一个 WP 即冒烟验证，风险早暴露 |
| 前后端并行冲突 | 代码冲突/返工 | 目录级写入范围隔离；路由/入口/配置等共享文件由 Lead 统一集成 |
| 数据统计口径 | 数据中心数字不可信 | 明确指标定义（docs/03 §8），日聚合任务可重跑 |
